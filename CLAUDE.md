# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

GitHub Action (`ai-code-rating/action`) that checks a repository's `ACR.md` against the [AI Code Rating](https://aicoderating.com) spec, with the same checks as the site's validator page. Used as `uses: ai-code-rating/action@v1`.

## Where the Checks Live

The checks are written once, in the site repo (`ai-code-rating/aicoderating.com`, file `src/assets/js/acr-check.js`), and shared by the validator page and this Action. Everything in `lib/` is generated by the site repo's `node scripts/sync-action.mjs`:

- `lib/acr-check.cjs`: the checks.
- `lib/acr-data.json`: the levels, spec versions, file name, and site URL, in the same shape as the site's `window.ACR`.
- `lib/js-yaml.cjs` and `lib/js-yaml.LICENSE`: the YAML parser (MIT).

Never edit `lib/` here. Change the checks or levels in the site repo, re-sync, then test here.

`check(text, { acr, yaml, fmt, today })` returns a list of results, each `{ level, msg, line }` where `level` is `error`, `warn`, `ok`, or `info`. The result that holds a valid rating also has `rating` and `meaning`, and `index.cjs` uses it to find the rating. Results from `checkBadges` add a `file`, since they point at the README instead of `ACR.md`.

## Files

- `action.yml`: inputs `path` (default `ACR.md`) and `fail-on-warnings` (default `false`; warnings such as a rating last checked over a year ago pass unless it's `true`), outputs `rating`, `errors`, `warnings`. Runs on `node24`.
- `index.cjs`: reads the inputs from `INPUT_*` environment variables, runs the checks and reports each result as a workflow command annotation (`::error`, `::warning`, `::notice`) on the right line of the file, a table in the job summary and step outputs. No `@actions/core`, no dependencies, no build step. If the `path` file doesn't exist, `findFile` uses one in the same folder whose name differs only in case, as the spec says tools should. Summary table cells have newlines stripped, since messages can quote keys from the file. An empty file is an error here (on the validator page it's just a prompt to paste). It also has the one check that isn't shared with the validator page, since it needs the repo: `checkBadges` finds the README GitHub shows (`.github/`, then the root, then `docs/`) and warns about any `img.shields.io/badge/ACR-xxx-` badge whose rating differs from `ACR.md`'s. `ACR_TODAY` fixes today's date, for tests only.
- `test/run.cjs`: runs `index.cjs` as GitHub would on sample files and checks the exit code and outputs of each. Run with `node test/run.cjs` (`-v` shows the output). There's no option to run a single case. Each case in the `cases` array is `[name, ACR.md text (null for no file), inputs, expected { exit, rating, errors, warnings }, other files { path: text }]`, written to a temp folder used as `GITHUB_WORKSPACE`, with today fixed at 2026-10-06. Keep its samples in step with the site's `scripts/test-validator.cjs`.
- `.github/workflows/test.yml`: runs the tests, then the Action on this repo's own `ACR.md`.
- `.github/dependabot.yml`: monthly grouped updates for the actions in the test workflow. These don't touch the Action itself, so they aren't a release.
- `CHANGELOG.md`: date-grouped entries headed `## YYYY-MM-DD: vX.Y.Z, Title`, or `No Release` in place of the version when nothing users run has changed.
- `ACR.md`: this project's own rating. Keep its `updated` date current.

To try the Action by hand on a folder: `GITHUB_WORKSPACE=/path/to/repo node index.cjs`. Without `GITHUB_OUTPUT` and `GITHUB_STEP_SUMMARY` set, it only prints the annotations and verdict.

## Releases

Tag each release `vX.Y.Z` and move the major tag (`v1`) to it, since users reference `@v1`. A change to the checks, the levels (for example a new spec version), or the bundled js-yaml is a new release.

After the commit is pushed, the steps are:

1. Tag it with lightweight tags, like the existing ones: `git tag vX.Y.Z <commit>` and `git tag -f v1 <commit>`.
2. Push the new tag with `git push public vX.Y.Z`.
3. Move `v1` with `git push --force public v1`. This is a force push, so it waits for Greg's go-ahead, separately from the normal push.
4. Create a GitHub release, which the Marketplace listing reads: `gh release create vX.Y.Z --title vX.Y.Z --verify-tag --latest --notes-file -`, with the version's `CHANGELOG.md` bullets on stdin.

## Commits

Every commit carries a `Co-Authored-By: Claude Code <noreply@anthropic.com>` trailer when Claude Code changed code in it, not just docs such as the README, `CHANGELOG.md`, `CLAUDE.md`, or `ACR.md` (keep the email: GitHub only shows a co-author written as `Name <email>`), and `Reviewed-By: Codex` only when Codex actually reviewed it. A commit of only hand edits gets neither. `ACR.md` mentions both. The history was reset to a single Initial Commit on 2026-10-07; don't rewrite it again.
